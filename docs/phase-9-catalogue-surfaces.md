# Phase 9 — Catalogue Surfaces (S1 Home, S2 Listing, S3 Product detail, S8 Categories)

**Objective:** compose the four public browsing screens to their designed layouts, keeping every existing filter, variant-selection and add-to-cart behaviour intact.

**Prerequisites:** Phase 8 DoD, including the list of unvariant `<Button>` call sites produced by task 8.3.

**API surface:** `GET /categories`, `GET /products`, `GET /products/:slug`, `GET /products/:id/reviews`, `GET /shipping/fee`. All Public, all already implemented — **this phase adds no new call.**

**Decisions and gaps recorded by this task**

- **The panel was not "already a `Sheet`".** This bullet's original text credited `products-filters.tsx` with the drawer already being done. It was not: the `Sheet` was `sm:hidden` and mobile-only, desktop rendered the same controls inline with no drawer at all, and the mobile sheet's "Apply" button was a `SheetClose` that committed nothing. Every interaction wrote straight to the URL — including one navigation **per keystroke** in the price inputs. 9.3 was a rewrite of the listing shell, not a restyle.
- **GAP-13: no category description field.** The designed title band pairs the heading with a justified 56ch intro. `GET /categories` carries no description, and the design's own copy makes a count claim ("Twelve pieces") that would contradict `productCount`. The paragraph is **omitted**; nothing was invented. Registered in `docs/backend-contract-gaps.md`.
- **The heading is an `h1`, not the documented `h2`.** The handoff marks it `h2` only because its artboard nests every screen under a frame heading. The real page has no other `h1`. `globals.css` already sets `h1,h2 { font-weight: 400 }`, so this is visually identical and gives the page a correct document outline. With no `?category=`, it reads **"The catalogue"** — the design only shows the category case.
- **"N of M pieces" costs no extra request.** N is `meta.totalItems` for the active filters; M is the selected category's `productCount`, or the sum across categories when none is selected. Both come from `getCategories()`, which the feature already awaits and which is cached for 300s. Verified live: `?category=dresses&sizes=S,M&colors=Black` renders "1 of 3 pieces".
- **`Filter (N)` counts filters, not products** — matching the design's "Filter (5)" against its five applied tags. It is derived from the URL alone, so the trigger never waits on data.
- **One promise, two Suspense boundaries.** `getProducts` is started once in `features/products/index.tsx` and shared by the piece count and the results grid, so the controls row stays interactive while the grid streams. Each consumer carries its own error boundary: the grid keeps `SectionErrorBoundary`, while the count uses `catchError(() => null)` so a failed fetch hides the count instead of raising a second error surface or crashing the page. The `Filter` trigger and the applied tags sit outside every boundary on purpose — they are pure URL state, so filtering survives a failing catalogue request.
- **`Show N pieces` never states a number it cannot back.** The drawer issues no fetch on open, so the count for an *edited* draft is unknowable. The footer primary reads `Show N pieces` while the draft matches the applied filters and switches to `Show results` the moment it diverges. A failed count promise degrades to the same `Show results` rather than crashing the drawer. Verified live.
- **The search input left the listing.** The design has none, and `header-nav-area.tsx` and `sidenav.tsx` already wrapped `SearchField` in a working `<form method="GET" action="/products">`. The listing's input and its 400ms debounce are gone; `?search=` now surfaces as a removable APPLIED tag. **Still open:** `SearchField` accepts a `defaultValue` nobody threads, so the header box blanks after a search. Reflecting it needs `useSearchParams()` in the shared header — a layout cannot read `searchParams` — which is shell work outside this task.
- **The Featured toggle was dropped, not its parameter.** The design has no such control. `?featured=true` still arrives from the home bands and is now removable through its own APPLIED tag — the only exit from that URL, since the drawer no longer offers one.
- **`category` is not an applied tag** — it is the heading. That is what makes the phase doc's "Clear all resets to the *category default*" coherent: the link drops every other filter and the sort, and keeps `?category=`.
- **`buildProductsHref` moved and generalised.** It left `products-pagination.tsx` for the plain params module beside `toGetProductsParams`, and now takes `Partial<ProductsSearchParams>` overrides where `null` removes a filter. Values sitting on their default (`sort=newest`, `page=1`, `limit=20`) are omitted, so a cleared listing lands on a bare `/products`. This one function backs pagination, every `✕`, and "Clear all" — which keeps the whole applied-filter row and the pagination pure Server Components with no client JavaScript.
- **`formatEGPRange` added to `lib/format.ts`.** `formatEGP` appends " EGP" to every value and forces two decimals, which would render the design's "500 – 2,500 EGP" as "500.00 EGP – 2,500.00 EGP". Filter bounds are numbers a shopper typed, not server-quoted money, so they get their own formatter — this is not client-side money math.
- **Two Base UI traps worth recording.** (1) `SheetContent`'s `data-[side=left]:w-3/4` is an attribute-selector variant at specificity (0,2,0), so a bare `w-[340px]` loses and tailwind-merge will not strip it; the override must itself be variant-prefixed. (2) `Select.Value` renders the raw item value unless given a formatter function, which surfaced a literal `top_rated` in the sort control until it was passed a label mapper.
- **`SheetContent` gained an `overlayClassName` prop.** It rendered `<SheetOverlay />` with no props, so the backdrop was unreachable; the drawer needs a light scrim rather than the modal-dark default. Additive and backward-compatible — the file already carried a comment anticipating this exact change for S2.
- **Codex review findings, all three resolved.** A review run against the half-landed tree flagged (1) a P1 TS2741 because the new required `appliedCountPromise` had no caller, (2) sorting unreachable, and (3) `featured` unclearable. All three were artifacts of reviewing Track A alone; the shell work closes each. Re-verified after: `bunx tsc --noEmit` clean, `bun run build` clean, 0 console errors.
- **Delegation note.** The drawer landed via Codex; the shell track hung after ~90 seconds with no file writes while still reporting "running", and was finished directly after cancelling it.
- **Still not verified — no data exists for it.** As in 9.2, the local catalogue has no product with `quantity <= 3`, so the DoD line on sold-out and low-stock cards remains unsignable on this screen too. It needs seed data, not code.
