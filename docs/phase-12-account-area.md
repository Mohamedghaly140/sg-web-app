# Phase 12 — Account Area (S10 Overview, S11 Addresses, S12 Orders, S13 Order detail)

**Objective:** compose the four signed-in screens to their designed layouts, and build the account overview dashboard and profile screen that do not exist yet.

**Prerequisites:** Phase 11 DoD — satisfied: `/contact` shipped in Phase 11. **Phase 6 (orders) must read `done`.**

**API surface:** `GET /users/me`, `GET /orders`, `GET /orders/:id`, `POST /orders/:id/cancel`, `POST /orders/claim`, `GET /addresses`, `POST /addresses`, `GET /addresses/:id`, `PATCH /addresses/:id`, `DELETE /addresses/:id`, `PATCH /addresses/:id/default`, `GET /shipping/fee`, `GET /wishlist`.

**Two of these screens are new work, not a re-skin.** `app/account/page.tsx` is currently an inline `EmptyState` placeholder, and `/account/profile` does not exist at all despite the Phase 8 sub-nav linking to it.

## Contract limits this phase must respect

Four parts of the designed account area cannot be built as drawn. All are filed in `docs/backend-contract-gaps.md`, and **none resolve in the design's favour**:

- **GAP-4 (escalated)** — `GET /orders/:id` returns no shipping address and no notes, so screen S13's `DELIVERING TO` and `NOTE FOR THE COURIER` band has no data. Omit the band.
- **GAP-7** — no receipt document and no re-send endpoint exists, so screen S13's Receipt card has nothing behind it. Drop the card; do not ship inert buttons.
- **GAP-8** — order lines carry `productId` but product detail is addressed by `slug`, so `View piece` cannot link. `Buy again` survives because `POST /cart/items` takes `productId`.
- **GAP-15** — order summaries carry no line previews, so S12 cannot show plates or names on every card. Hydrate only the newest in-progress order and keep the rest summary-only.

- **The panel's open state lives in the URL**, not in component state — a nuqs `address` param holding `"new"` or an address id (`features/addresses/hooks/addresses-search-params.ts` + `use-addresses-params.ts`, the mandatory two-file split). `Edit` and `+ Add address` are therefore `<Link scroll={false}>`, which let `address-list-item.tsx` **drop `"use client"` and become a Server Component**; only `DeleteAddressButton` and `SetDefaultAddressButton` remain client leaves. **Decisions and gaps recorded by this task**

- **The breadcrumb is now shared, not products-local.** `features/products/components/breadcrumb.tsx` was typed to `ProductCategoryRef` and could not express an order trail, so it was generalised to `components/shared/breadcrumb/` taking `items: { label, href? }[]` and the products copy was deleted. It carries an optional `back` override for the narrow-width collapse: the default is the last *linked* crumb, which is right for S13 (`‹ Orders`), but the PDP's documented collapse is `‹ <category>` to `/categories/[slug]` (`docs/screens/product-detail.md` §"Narrow width") and its subcategory crumb sits after the category — without the override the PDP's back link silently retargets to the filtered listing. The breadcrumb renders from `order-detail-feature.tsx`, never from inside `OrderDetailView`, so the guest route cannot inherit an account trail. `OrderDetailView`'s old `back` prop is gone.
- **Heading levels are semantic, not the design's sizes.** S13 draws the order id at `h3` and the lines header at `h4`, but neither the account layout nor the guest tracking page renders a heading above the view, so following the design literally left both routes with no `h1`. The order id is an `h1` and the lines header an `h2`; the Classical 25px/20px treatment comes from the utilities, so nothing moves visually. The same defect stood in S11 and S12 — `features/addresses/index.tsx` and `orders-header.tsx` both opened at `h3` under the same headless layout. That is 12.3/12.4 code and was left alone here; **it was closed in 12.6**, which promoted both to `h1` with their class lists unchanged.
- **Per-line `Buy again` is serialised across the whole screen.** Each line's button is its own client leaf with its own mutation, so a `disabled={isPending}` local to one button does not stop a second line being clicked mid-flight. A guest on `/orders/track/[token]` may hold no `sg_cart_session` at all; two overlapping adds would both read an empty cookie, mint two anonymous carts server-side, and the losing cookie write would strand an added line in an unreachable cart behind two success toasts. Every button therefore shares the `cartKeys.current` mutation key and gates on `useIsMutating` for it. The cart page needs no equivalent guard — its per-item `inFlightItemIds` tracking allows concurrent lines, but a guest standing on the cart necessarily already holds the cookie.
- **`Buy again` reuses the cart primitive, not the order-scoped action.** `features/orders/actions/buy-again.ts` re-fetches the order and re-adds every line under `auth: "required"`, so it is wrong twice over per line and would 401 a guest. The leaf calls `useAddCartItem` (`auth: "optional"` + `cartSession: true`) instead. The order-scoped action and its S12 button are untouched.
- **GAP-16 filed.** `GET /orders/:id` and `GET /orders/guest/:token` carry `createdAt` and no transition timestamps, so the timeline dates only its first stage and renders `—` for the rest rather than interpolating.
- **`CancelOrderButton` gained optional `label` and `className`** so the rail can render a block "Cancel this order" without forking the shared leaf. Its `ConfirmDialog` copy and every existing call site's defaults are unchanged.
- **`order-detail-feature.tsx` lost its own page wrapper.** It was nesting `max-w-6xl px-4 py-8` inside `app/account/layout.tsx`'s `max-w-[1280px] px-4 py-8`, which narrowed the content column against the 340px rail. The guest tracking feature keeps its wrapper — that route has no layout above it.
- **Not verified — the browser checklist has not been run.** `bun lint`, `bunx tsc --noEmit` and `bun run build` all pass, but nothing here has been exercised against a live backend: the four-column timeline against a real PROCESSING/SHIPPED order, cancelling a PENDING order through the dialog (which also closes the still-unverified Phase 8 `AlertDialog` item), `409 INVALID_STATUS_TRANSITION` recovery, per-line `Buy again` on both routes including the anonymous-cart path, the claim card in the guest rail, and the PDP breadcrumb regression check are all still unchecked.

**Decisions and gaps recorded by this task**

- **`WishlistItem` was deleted rather than reused**, contradicting this task's own wording above. Once the list renders S2 cards, the component had no consumer, and keeping it would have meant two divergent presentations of the same entry. Its local `en-GB` `Intl.DateTimeFormat` went with it in favour of the shared `formatDate()` (`lib/format.ts`), which is fixed to `Africa/Cairo` and so is hydration-safe for the server-seeded list in a way the old formatter was not. Its `cldUrl()` call was also dropped: `ProductCard` deliberately drives Next `Image` from `sizes` instead of a fixed Cloudinary transform, and `docs/phase-7-classical-foundation.md` reserves `cldUrl` for small thumbnails where the mat dominates — a ~296px grid plate is the Phase 9 `sizes` case.

The classes carry Tailwind v4 trailing `!` for this reason; do not "clean them up". Confirmed fixed in the browser as Cormorant Garamond 25px/400.
